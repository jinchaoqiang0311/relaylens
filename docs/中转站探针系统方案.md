# RelayLens 中转站探针系统方案（可移植版）

> 一套对 AI API 中转站做「计费诚实度审计」的探针体系。核心信条：**每个上页面的数字都能回溯到一个带批次号的原始证据；测不出来就留空，绝不编造。**
> 参考实现：`relaylens/probe/`（TypeScript + Node ≥22 + SQLite，无框架依赖，静态站前端消费 JSON）。

---

## 1. 总体架构

```
config/sites.yaml          站点注册表(名称/base_url/key_env/分组声明/commerce声明/调度cron)
config/secrets/sites.env   各站 sk key(gitignore,与代码/发布目录隔离)
        │
        ▼
┌─ 探针任务(cli/调度器驱动) ──────────────────────────────┐
│ health      免成本探活(每5h)                             │
│ price       定价接口采集(new-api /api/pricing 等)        │
│ perf        首字延迟+流式真伪(真实请求,分/厘级成本)      │
│ tokens      Token计量线性度(查注入)                      │
│ billing     逐笔对账(真金白银:余额差 vs 应扣)            │
│ fingerprint 模型指纹差分(跨站基线,查掉包)                │
└──────────────────────────────────────────────────────────┘
        │ 每个批次:SQLite batches/rounds 表 + raw/ 归档(完整请求响应节选)
        ▼
audit log(hash 链 append-only,89+ 条,每次数据变更留痕可复查)
        ▼
sync.ts → sites.json(compare.tabs / realSites / details / meta)
        ▼
静态前端(榜单/比价/最低价/工具箱...)——纯消费 JSON,无后端
```

**关键设计**：数据层与展示层彻底分离；探针只写库和归档，前端只读一份 JSON；重采/重跑任何单任务不动其他数据。

## 2. 六类探针的方法与公式

### 2.1 health 探活（免鉴权成本）

- `GET {origin}/v1/models`（或轻量 chat 请求），记录 HTTP 状态、延迟、模型数；
- **401/403 鉴权门单独计数**：`DNS/TLS/路由全通`≠`可直接调用`，可达率口径要在页面写明；
- base_url 归一：裸 origin 补 `/v1`，已带 `/v\d+` 路径的不补（OpenRouter 型自带路径）；
- 返回 200 但 `model_not_found` 不算成功（new-api 常见假 200）。

### 2.2 price 定价采集

（详见另一份《中转站价格抓取与CNY换算方法论》，要点回顾）

```
到手价(¥/M) = 基础价($/M) × 组倍率 × 充值比例(¥/1美元额度)
基础价: tiered_expr → billing_expr 第一个 tier 体系数; 普通 → model_ratio × $2
主口径: 默认组 > 中位组; 全组价存 groups[]; 最低组只做"特价并列"展示
```

### 2.3 perf：真 TTFT + 流式真伪

```
TTFT = 发出请求 → 首个"内容 delta"到达的毫秒数(SSE 逐行解析 data:)
每站 8 轮短请求 → 中位数/P95/成功率/超时率(30s 无首字=超时)
```

**流式真伪必须用长输出专项**（短答案 2 个字单 chunk 是真流式的常态，判不了）：

```
发 3 次 ~200-400 字长输出请求,每次换措辞(不同站对不同 prompt 行为不同!)
chunks≥10 且 首末内容块跨度≥800ms → 真流式
chunks≤5 且 跨度<200ms            → 伪流式(整段缓冲)
3 次交叉出现                       → 混合(疑似多渠道路由)
```

- 跨站比较必须同模型（`pickModel`：先剔除非对话模型 image|video|t2v|embed|tts|moderation|rerank|sora|kling...，再按 deepseek→flash→国产→gpt/claude 优先）；
- 模型返回的 `model` 字段不可信（掉包站照样回显请求名），指纹见 2.6。

### 2.4 tokens：注入检测（Token 虚标）

```
发 3 段长度已知的唯一中文文本(随机打散防缓存): 30/200/1000 字
读 usage.prompt_tokens 做最小二乘拟合: fresh = slope×chars + intercept
注入量 = max(0, round(intercept)) + median(cached_tokens 异常脚手架)
注入 > 200 tok/请求 → 标红; 同时把自报 prompt_tokens ÷ 本地估算 = 用量通胀率
```

**铁律**：`cached_tokens` 是 `prompt_tokens` 的子集（fresh = prompt − cache），总 token 严禁 in+cache+out 相加。

### 2.5 billing：逐笔对账（真金白银，最硬的证据）

```
1. before = 站方余额端点读消费前余额(分)
2. 跑 N 轮已知用量的请求(短/缓存/长各一型)
3. after → 实扣 = before − after
4. 应扣 = Σ(fresh/1M×输入价 + cache/1M×缓存价 + completion/1M×输出价) × 500000
   (500000 = 每美元额度数;new-api 默认约定)
5. 偏差% = (实扣−应扣)/应扣
   容差: max(2 quota, 1%) 内算 matched(整数取整误差,短请求天然偏大要说明)
6. 校准因子 = 实扣÷应扣 → 只出验证角标,不乘进展示价
   · 因子按模型生效(calibModels 记录覆盖清单,禁止外推)
   · 因子绑定价表内容哈希 priceHash(重采但价没变→校准仍有效)
7. 失败分类学: "额度不足/余额不足/停用" = 测试账户没钱(信息级),
   不是站点不可用(critical)——ops 告警必须区分
```

账单流水对账（有消费日志导出的站）：站方 log 逐条 vs 我们记录的请求，matched/mismatched 计数即榜单「计费测试」列。

### 2.6 fingerprint：模型指纹差分（查掉包/降级）

```
题库 v1 = 4 确定性题(数学复合/日期逻辑/陷阱题/代码输出,temperature=0 有唯一答案)
        + 4 风格题(解释结构/列表格式/拒答模式/代码风格)
基线选择: 跨站差分——拿被测站 vs 另一家中转站同模型的回答比(没有官方基线时的代理)
         跨站基线置信度 ×0.8,结论只到"疑似"级
相似度 = 确定性题精确匹配 + 风格题结构相似度(长度比/格式/关键词)加权
≥85 通过 / 70-85 存疑复检 / <70 疑似掉包(标红复核,非终局定论)
```

**防干扰记录**：站方网关可能拦截考题（返回"内容审计命中风险规则"）污染样本——fpDetail 取「最近一批**有有效样本**的」结果并记录其后空跑批次，防止 0 样本批次抹掉真实测量。终局判定需官方基线比对（拿官方 key 跑同题库）。

## 3. 模型标识治理（比价能对齐的前提）

- **登记表 CANON**：全站唯一模型清单（id/显示名/家族），榜单/比价/最低价的选择栏都从它派生；
- **归一化 canonName**：去 `vendor/`、去 `:batch`、点→横、循环剥 `-preview/-customtools/-latest/-image`，然后**精确等值匹配**（防 `-flash/-hc/-pro` 派生名误并）；
- 不在登记表内的模型不进任何页面（宁缺毋错）。

## 4. 证据链与审计

- **raw 归档**：每批次存完整 summary + 请求/响应节选到 `store/raw/`，页面任何数字可按批次号（RL-RC-YYYYMMDD-NNN）复查；
- **hash 链审计日志**：append-only，每条含前条哈希，DB↔JSONL 定期对账；改一条历史会断链；
- **批次号原子预留**（id_reserve）：批量任务先占号再执行，号宽不写死（写死 3 位曾在 999/日时静默卡死调度）；
- 重跑单站任务**必须基于全部在册站点重建 dist**——单站重跑覆盖全站产物是事故源（实测发生：常驻调度带旧代码重采，把 17 模型锚点覆盖回 9 个）。**改解析器/模型名单后必须重启调度进程**。

## 5. 调度

- cron 表在 sites.yaml（如 health `0 */5 * * *`），按成本分级：免费任务高频、真实扣费任务低频或手动；
- 调度器是长驻进程 = **代码快照**：更新解析逻辑后不重启，它就用旧代码覆盖新数据（踩过，见 §4）；
- 探针错峰：站方慢/超时 30s 常态，串行 + 轮间隔 1-1.2s，防并发污染对账余额。

## 6. 诚实性框架（这套系统的灵魂）

1. **三种空值语义严格区分**：`不适用`（类目天然 N/A，灰虚线）/ `未测`（还没跑，琥珀色）/ `未声明`（需站方给数，如充值比例）——排序时空值永远沉底，不参与打分；
2. **数据层级徽章**：做过账单级对账 = `billing`(可称"实测")；只有免费监测 = `passive`(只能称"监测中")，不给分数；
3. **校准不改价**：实扣因子只产出验证角标（✓实扣一致 / ⚠标价≠实扣±X% / 未实测·按公式折算）；
4. **疑似≠定论**：指纹未通过等标注一律带"复核信号"措辞 + 申诉通道；被干扰的样本如实注明；
5. **门面数字防编造**：首页统计（已实测家数/核验笔数）只统计可回溯到证据的量，数字难看也比编造值钱；
6. **推广与评分隔离**：CPS 佣金率等商业字段在服务端参与排序后**从下发 JSON 中剥离**，前端只见 url/coupon；榜单名次不售卖的叙事要有架构保证而不只是口头承诺。

## 8. 移植清单（新项目最小闭环）

| 优先级 | 模块 | 依赖 |
|---|---|---|
| P0 | price 采集 + canonName 归一 + 模型登记表 | 一个 HTTP 客户端 |
| P0 | 三因子到手价 + 默认组口径 + 三空值语义 | — |
| P1 | perf(TTFT+流式专项) | SSE 解析 |
| P1 | tokens 注入检测 | 本地 token 估算(CJK≈1字/元) |
| P2 | billing 对账 + 校准因子(按模型/绑哈希) | 站方余额端点或流水导出 |
| P2 | fingerprint 差分 | 题库设计 |
| P3 | hash 链审计 + raw 归档 + 批次号 | SQLite 即可 |

## 9. 已知边界（对使用者诚实）

- 所有测量反映**测量时点 + 我们节点/分组**的表现，不代表其他用户/时段/分组；
- 跨站差分指纹是代理基线，掉包终局判定需要官方 key；
- 缓存命中率只能来自消费日志对账，不能远程重测；
- 站方可以针对探针改变行为（被观测效应在审计场景是特性不是 bug——但要在方法论页写明）。
