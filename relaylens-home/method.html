①账单级实测流程

每 6 小时,检测系统对每个收录站点执行一轮完整付费测试。核心原则:用真实充值的钱、调真实模型、留下真实账单——不是免费健康检查,不是爬虫抓页面。

1

注册与充值

以标准流程注册站点账号(不做特殊标记),用平台运营资金真实充值。充值金额控制在能完成 3-5 个检测批次的最低档,既是成本控制,也是对"最低充值门槛"这一风险指标的天然采样。

输出:充值记录、到账金额、充值比例实测值
2

标准混合模型测试(10 轮)

每批次固定 10 轮:5 轮旗舰模型(Opus/最大档)+ 3 轮主力模型(Sonnet/中档)+ 2 轮低价模型。固定输入语料(公开测试集,版本号管理),覆盖短上下文、长上下文、流式输出三种模式。

输出:每轮 usage 明细、耗时、model 返回值、原始 Response
3

对账核验

逐轮计算"理论应扣"(按站方公示价格 × 实际 token 用量)并与面板流水"实际扣费"比对。判定容差:|实扣−应扣| ≤ max(2 quota, 1%) —— 2 quota ≈ $0.000004 额度,只吸收 quota 整数取整(超短请求的相对偏差因此可到 2~3%,绝对量级可忽略);大单按 1% 相对容差,站方篡改倍率产生的系统性同向偏差不受此容差影响,仍会被逐笔抓出。任何偏差超容差触发复核流程;连续 3 批次 >3% 且站方 72 小时无法解释,列入黑名单。

输出:逐轮对账表、批次偏差率、面板流水存档
4

模型指纹比对

同一组探针问题(复杂推理、代码生成、知识边界、拒答模式)分别发给中转站与官方直连,对响应特征做相似度比对。相似度 ≥85% 通过、70-85% 存疑(复检)、<70% 未通过。不依赖"问模型你是谁"——系统提示词可以让模型说谎。

输出:指纹相似度、能力探针得分曲线
5

缓存命中统计

10 轮中固定 4 轮使用相同长前缀,检测第二轮起的 usage 中缓存命中字段是否真实增长、扣费是否按公示缓存价执行。同时记录站方是否公示缓存价、缓存读价与输入价的比值。

输出:命中率、缓存价/输入价比、是否"不算缓存"
6

数据入档

全部原始数据(含 API Response JSON、面板截图、批次号、时间戳)写入开源数据仓库,站点详情页逐条展示。任何指标变动都可回溯到具体批次。

输出:存档编号 RL-RC-YYYYMMDD-NNN

③评分公式与权重

单一综合分掩盖场景差异——写代码最在乎缓存,日常聊天最在乎首字延迟。因此每站有独立的多场景评分,权重按场景第一决策变量设计。分数强制携带覆盖率与置信度,样本不足显示"数据不足"而非低分。

权重版本 2026-10-22.1 · 本表与探针计算代码共用同一份 weights.json(网页说什么,代码就算什么)。本次变更:①计价口径纠偏——站方公示价恢复为其原始额度单位(new-api 系 $X/M,与站方页面一致),人民币只作为「到手价 = 额度价 × 站方声明的充值比例」出现,比例未声明不给人民币价(此前用 1$=¥7.1 折主价,造出站方页面不存在的数字);②决策页「TTFT」统一改称「首字延迟」;③榜单站点列瘦身、商业信息独立成列;④报价标出来源分组与「最优价口径」。评分口径与数值不变。.6 修订:文档化对账判定容差 max(2 quota, 1%),无计算变化。.5 修订:注入开销落库按站实测(aixoras 4858 / aicost 3959),EP 拆分按站,渠道混合标 unstable。.4 修订:编程榜新增独立桶 SR(流式真实性,权重10),弃用「并入 PF」方案(沙盘证明对首字延迟触底站零增量)。.3 修订:PF 改用专用流式探针测真首字延迟,新增伪流式率指标,超时率首次持久化。2026-10-22 修订:首字延迟 PF 由忙/闲双桶较差值(悲观值)改两桶中位数均值(用户拍板),榜单同时展示忙/闲双值。更早:①注入开销以「场景有效价格」吸收,避免双重计分;②计量一致性并入计费诚实;③超时率并入稳定性(慢≠挂,0.3 倍扣减);④未测指标重归一化而非零分;⑤稳定性增加时间跨度门槛(≥45 分钟),防止短时猛采刷样本。历史版本见开源仓库 changelog。
综合分 = Σ( 指标归一化值 × 场景权重 ) × 置信度因子 // 置信度 < 0.8 不展示

归一化:每项指标线性映射到 0-100(如可用率 95%→0 分,100%→100 分)。未测指标不惩罚:剩余权重重归一化;覆盖率(已测权重占比)<60% → 评分置空「数据不足」;60-80% → 展示但挂低置信标。置信度 = 样本达标比 × 覆盖率 × 基线折扣(跨站差分指纹 ×0.8)。稳定性样本需同时满足次数 ≥12 且时间跨度 ≥45 分钟——避免短时猛采刷出虚假置信。

PF 锚点为初版统一值(≤1s=100 / ≥8s=0),而推理模型自带思考耗时、号池注入的 4392 token 也需预填充——因此 PF 偏低部分是注入开销的连带症状而非独立缺陷。我们不会为了让数字好看而回调锚点;分模型测量通道已于 2026-10-10 上线(perf 探针在主模型之外自动加测推理档,task=perf_reasoning,不计入评分),锚点校准待分模型数据积累后按「沙盘模拟→用户拍板→升版本→公示」流程走。同一批次起,perf 采样改为双窗口(工作日 10:30 忙时 + 每天 22:30 闲时):同一站闲时 2.1s / 高峰 14.8s 的实测证明单时点采样让分数被运气摆布——PF 取忙/闲两桶中位数的均值(2026-10-22 用户拍板,由悲观较差值改均值),榜单展示忙/闲双值;单桶缺样本时如实标注。

有效价格(EP) = 场景参考负载下的真实成本 ÷ 官方直连同负载成本,对数映射(5% 官价=100 分,官价=20 分)。注入开销在此被定价:每站由 token 计量对照实验自动推导并落库(2026-09-30 实测 aixoras ≈4858 / aicost ≈3959 tok/请求,缓存/fresh 拆分亦按站实测),实测短请求场景下,额度价 $0.9/M 的号池渠道真实成本反超官方直连,这正是 EP 存在的意义。

④更新机制与置信度门槛

更新节奏

  • 健康检查:每 5 小时一次的免鉴权探活请求(不计 token,只确认端点可达)。代价说清楚:站点宕机最长 5 小时后才被我们发现,所以榜单趋势列是「近 72 小时 · 每 6 小时一格」而不是逐小时;新站要攒够 ≥12 次样本才出分,按这个节拍约需 3 天。
  • 完整付费批次:每 6 小时,10 轮标准混合模型测试(对账/指纹/缓存的时效来源)
  • 价格采集:随完整批次同步,含分组倍率与充值比例复核
  • 榜单刷新:每批次完成后即时刷新,页面显示"最后更新"时间戳

置信度规则(反小样本误判)

  • 样本 < 12 批次或跨度 < 45 分钟 → 不展示分数,标注"数据不足"
  • 置信度 = min(1, 批次数 ÷ 12),< 0.8 的分数带"低置信"标识
  • 新站需连续 14 天 正常检测才进入正式榜单
  • 黑名单判定要求连续 3 批次证据(排除单批次网络抖动)

已知局限(诚实披露)

  • 分组口径(最重要的一条):new-api 系中转站的一个 API Key 只能绑定一个分组,因此我们的"站点分"实际是"该站某一个分组的分"。详情页与榜单已标注实测分组;同一站的其他分组(尤其特价分组)在未拿到对应测试额度前不测不打分。
  • 检测节点:现阶段只有 1 个 中国大陆检测节点,海外直连与不同运营商环境的表现未覆盖;社区探针节点尚未开放,开通后本条会更新。
  • 额度价、到手价与汇率(重要):中转站后台的计价单位是额度(500000 quota = 1 美元额度),站方页面上的 "$1.75/M" 是额度价,不是美元现金价。你真正花的人民币 = 额度价 × 充值比例(常见 ¥1 = 1 美元额度,也有站按 ¥7.2 = 1$)。所以我们:①标价保持站方原始额度单位,让你在站方页面看到的数和我们的一致;②人民币到手价只在站方声明了充值比例时给出,未声明就写「不给人民币价」,绝不拿汇率猜;③跨站排序与奖牌一律用额度价(同单位才可比);④汇率 1 美元 = ¥7.1 只用于官方直连(它确实是美元现金支付),口径常量在 weights.json → pricing_display,生效日 2026-10-02。
  • 比例和倍率不能单独解读:充值比例(多少人民币 = 1 美元额度)与模型倍率是同一笔价格的两种写法 —— 有站把倍率抬高一个数量级、再把充值比例写成 1¥=10$,到手价其实与同行相当。所以我们不用充值比例判断贵贱或风险,只比最终到手价;比例反常只作为「去核对倍率表」的线索。风险结论一律来自测得出来的量:逐笔对账偏差、模型指纹、超时率。
  • 时间窗口:实测数据是时点数据。渠道会换、倍率会调、号池会枯竭 —— 请看页面上标注的"最近审计"日期,充值前建议用工具箱自测一次。
  • 指纹判定:跨站差分基线存在少量误判可能,所以我们设"存疑"档并复检多轮取中位,而不是直接判死刑;当前基线是另一家中转站而非官方直连(置信度已按 ×0.8 折算)。
  • 探针语料:覆盖多种能力维度但不可能穷举你的业务场景;你的真实负载表现可能与探针不同。
  • 三种空值各有含义,别混着读:不适用(灰虚线)= 这一列对这家没有语义,永远不会有值(例:官方直连没有「中转扣费诚实」这一层);未测(琥珀)= 我们能测但还没测,是能力缺口(例:官方端点需要 key 才能跑付费流式探针);未声明 = 这类数据只能由站方给出或我们人工核实,没有第三种获取途径。榜单底部的官方直连与海外聚合是参照系,不参与中转榜排名,只回答「要不要走中转、中转比官方贵多少」;它们的「可达率」按免鉴权探活口径统计(401 鉴权门算可达),与中转站的「可用率」(鉴权后真跑出内容才算)是两把尺子,不可横向比较。
  • 商业信息分两档来源:支付方式 / 充值比例 / 起充金额 / 发票 / 退款没有任何探测路径能验证(我们不替站方保管账单,也不会去访问站方后台)。因此这类字段只有两种：站方入驻声明(通过入驻或认领表单提交,默认视为站方承诺)与人工核实(我们自己在站方页面看到并记录,带核实日期,界面标 ※)。二者不可混读:标 ※ 的内容不是站方承诺,充值前请以站方收银台实时显示为准。未取得的字段一律显示「未声明」,不猜、不留灰位。

我们相信披露局限本身就是可信度的一部分 —— 一个说自己没有局限的测评站,你本来也不该信。

⑤中立性声明:钱从哪来,边界在哪

测评站最大的风险不是测不准,而是"被充值方影响"。这一节说清楚我们的收入结构,以及它们各自不能碰什么。

永不做的事

  • 不卖排名、不卖"去黑名单"
  • 排名混入推广内容(优惠码、主观好评)
  • 对检测通道返回与真实用户不同的响应
  • 收受站点"送测额度"改变计费口径(收了必须公示,只用于测试)

收入结构(均不触碰排名)

  • 标注清晰的合作推荐位:仅首页"编辑精选"区,卡片右上角标"含推广链接";先过实测门槛(标红复核中、指纹未通过的一律排除),再按 综合得分 → 佣金率 → 活动有效期 排序;佣金率与有效期只在服务端参与排序、不下发页面。没有合格合作站时该区域显示空态,不摆假优惠
  • 企业定制报告:按需采购维度的深度分析

结构性防火墙

  • 推广与评分在数据层物理隔离:推广位读 promo.yaml,评分链路只读探针数据库与 weights.json,两者无交集 —— 佣金率不参与任何桶的计算,改推广配置不会动一个分数
  • 原始响应归档写入即不可变(同名批次直接报错拒绝覆盖);人工改动一律留痕 → ⑥ 审计日志
  • 我们不假装没有收入:赚推广佣金是事实,但排名买不动是机制保证的 —— 信任靠结构,不靠人格
  • 算法每次调整公示变更日志 → 见下方 ⑥ 审计日志(机器自动补记,非手写)
  • 送测额度、合作站点在每张卡片与详情页强制披露

⑧常见质疑,正面回答

"你们自己也是中转站利益链的一环,凭什么信你?"
凭结构,不凭人格。我们确实有推荐位收入,但:①收入依赖排名可买的话,产品就死了——用户来这儿就是因为不信别处;②检测数据开源可复现,榜单数字买不动,能买的只有"数据合格站里的曝光位";③黑名单站永久解除合作,这是我们砍自己收入的规定。最终判断权在你:所有数据都在,欢迎逐条验。
"扣费偏差 1% 的红线会不会太严/太松?"
1% 来自实测分布:计费系统的四舍五入与汇率折算自然产生 ±0.5% 以内误差,健康站点批次均值集中在 0-0.5%。超过 1% 说明计费逻辑有主动修改嫌疑;3% 以上配合"偏差同向"(只多不少)基本可排除巧合。阈值本身在年度评审时可调,调整会公示变更日志。
"指纹相似度 85% 的阈值有依据吗?"
来自对照实验:同一模型不同温度/采样参数的自对比相似度约 93-98%,不同代际模型(如 Opus vs Sonnet)交叉相似度约 60-75%。85% 落在两个分布之间,是"同模型不同配置"与"不同模型"的分界。70-85% 的"存疑"档就是为了承接这个灰色地带——配合能力探针复检,而不是一刀切。
"检测会不会被站点针对性优化(检测通道给好结果,真实用户给差结果)?"
这是已知攻击面,叫"差异化投毒"。三层防御:①检测账号与普通注册流程一致,无特殊标记;②部分批次来自社区探针节点(真实用户网络环境,站方难以区分);③用户举报通道作为交叉验证——真实用户体验与检测数据系统性不符时触发深度核查。一旦实锤差异化投毒,直接列黑名单(列入标准第 4 条)。
"你们自己会不会哪天跑路?"
合理的担忧。缓解措施:全部数据与脚本开源,即使本站消失,社区可以 fork 继续;算法与历史数据不依赖任何个人;也没有预付费订阅资金沉淀。评测站的生命周期应该比被评测对象更长,这是我们对自己的要求。

还是那句话:榜单只信账单,不信嘴
